# 维护个人主库

主库是本技能所在目录的上两级，先读 [AGENTS.md](../../AGENTS.md)。若当前环境只有技能副本，先找到用户已提供的主库位置；不要把副本当原件，位置未知时询问。

## 什么值得保存

- 用户在任何对话里明确陈述关于自己的事实或长期习惯（身份、背景、设备与环境、做事方式等），即使没说“记住”，也直接更新 [个人信息](../../profile/about.md) 或 [个人偏好](../../preferences/core.md)，不只存进当前 agent 自己的记忆（2026-10-14 用户要求）。从行为推测出的仍只作候选。
- 用户明确要求“记住”“以后都这样”，或纠正长期习惯：更新 [个人偏好](../../preferences/core.md)，文章风格更新 [写作偏好](../../preferences/writing.md)。临时要求只在当前任务生效。
- 用户明确提供或纠正个人背景：更新 [个人信息](../../profile/about.md)，对会变化的身份保留陈述日期。
- 用户要求改变可复用工作流程：编辑对应 skills/ 原件，保留适用条件与最新纠正。
- 创建、迁移或确认项目入口变化：更新 [project map](../../PROJECT_MAP.md) 中名称、用途、入口及最新上下文位置，不把进度日志搬过来。

完成相关任务前检查一次上述条件。用户已经明确要求保存或明确陈述的就直接落盘；仅凭观察推测出的喜好不保存，需要确认时提出具体候选。没有值得沉淀的变化就不修改，不在每次回答后增加维护提示。

## 怎样维护

1. 先读目标原文及必要的 [来源](../../SOURCES.md)，确定是补充、替换还是仅限本次。新明确纠正优先，避免并列矛盾规则。重要变更简短注明日期和来源，不复制聊天全文。
2. 检查 Git 工作区与远端；有网络时先 fetch，只有干净且可快进时拉取。保留未提交修改；分叉需合并，不强推。离线可先保存本地并明确尚未同步。
3. 做最小内容修改，核对链接可读、技能 frontmatter 有 name/description（改动时同步 `.claude/skills/` 下的同名入口和 AGENTS.md 所列各机器的用户级安装，并提醒用户重新打包上传 claude.ai 副本）、没有失效规则与个人事实推测。纯文字修改不引入管理程序或自动化。
4. 用户授权同步 GitHub 时，只提交本次已检查的文件并正常推送；核对远端提交后才报告已同步。否则仅报告已保存本地。其他设备通过拉取获取更新。只改 `profile/` 与 `preferences/` 的提交已获长期授权（2026-10-14）：核对后直接提交并推送，不再询问；涉及其他文件仍按本条先获授权。

## 收集候选

用户说“收集候选”或既有的每周调度触发时，汇总各 agent 私有记忆里主库还没有的个人信息与偏好：
1. 读取本机能读到的记忆：Codex（`~/.codex/memories/memory_summary.md`）、Command Code（`~/.commandcode/taste/` 下各 taste.md）、Claude Code（`~/.claude/projects/*/memory/`）、Notion Memory（有连接器时）。读不到的如实列出。
2. 与 [个人信息](../../profile/about.md)、[个人偏好](../../preferences/core.md)、[project map](../../PROJECT_MAP.md) 比对，只留新增或与主库冲突的内容；只属于某个项目的约定留在该项目，不进主库。
3. 用编号列给用户，每条注明来源及其置信度或原话；用户回复编号（可附更正）后再写入，并在 [来源](../../SOURCES.md) 记一行。不把候选当事实，不修改各 agent 的记忆。

不写凭据，不迁移账号授权，未经用户明确要求不新建调度；日记、日程、目标和任务明细按 project map 去原系统维护。汇报只需说明保存了什么、改到哪里、是否已同步。
