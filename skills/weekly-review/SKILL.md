# 每周回顾

读取 [资料导航](../../PROJECT_MAP.md)。按 Asia/Shanghai 自然周（周一至周日）定义周标识，明确本次实际覆盖到哪一天，不能把尚未发生的周末当作已回顾。

先查询原回顾历史，判断该周是否已经生成完整总结。现有约定是周五正常生成、周六查漏兜底；只有配置调整、失败运行或讨论不算完成。Hub 不迁移调度，不另建完成记录数据库。

1. 实时读取 Notion“目标和工作计划”，以当前活跃目标、该周状态变化及上次回顾为基线。不能只查活跃目标而漏掉本周刚完成或暂停的目标。
2. 每个目标交代状态变化、可验证成果、适合的量化推进、差距、卡点和已明确的下一步。活动和结果分开；讨论、计划、一次测试不等于目标完成。无可靠新增则明确说“本周无新增记录”。
3. 检查本周有实质内容的会话、项目进度等来源，按主题总结其他技术、学习、调研、文档、生活事务与决定。已经归入目标的内容不再重复；其他工作不强行挂到目标。
4. 忽略纯寒暄、重复确认与没有形成结果的零碎操作；记录访问不全时说明范围，不声称完整覆盖。
5. 输出“目标变化／目标推进／其他交互／卡点／下周重点”。目标是主体，其余精炼但保留实质成果。

在原自动化执行时，将周标识、覆盖窗口、摘要与成功时间写回其已有回顾历史并验证，用于去重和下次对比。普通手动请求先在当前会话交付；只有用户要求或原流程已授权时才更新外部历史。新 agent 无法读取旧会话时，使用已提供的其他来源并明确缺口，不假装可访问。
